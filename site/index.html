Connect your AI

Zeusi works with any assistant that speaks MCP, the open standard for AI connectors. Paste one URL and sign in. Zeusi then asks your assistant to search it before answering, and to cite what it finds.

Zeusi is a shared memory for decisions, digs, parked items and locks, named after a cat. Through a connector, Zeusi reads your workspace. In a personal workspace it can also fill it: it writes only into that workspace, and only after you approve a preview.

Server URL

https://mcp.zeusi.dev/mcp

Pick your app

Claude (web & Desktop)

  1. Go to Customize > Connectors, click + Add, then Add custom connector.
  2. Name it Zeusi, paste the server URL https://mcp.zeusi.dev/mcp and click Continue.
  3. Under Authentication, choose Sign in now. Under OAuth client, keep Use Claude’s published identity (Recommended), or pick Register automatically.
  4. Click Add, then sign in.

Claude Code

  1. Add Zeusi in your terminal: 
    claude mcp add --transport http zeusi https://mcp.zeusi.dev/mcp
  2. In a Claude Code session, run /mcp and sign in to zeusi (or run claude mcp login zeusi).
  3. Sign in with GitHub and approve access.

ChatGPT

  1. Open Plugins, click +, then Add custom MCP server.
  2. Enter a name (Zeusi). Under Connection, paste the server URL. Under Authentication, choose OAuth.
  3. Tick I understand and want to continue, then click Create as a plugin.
  4. Install the plugin, sign in, and use it in a chat with @.

Cursor

  1. Add Zeusi to ~/.cursor/mcp.json: 
    {
  "mcpServers": {
    "zeusi": {
      "url": "https://mcp.zeusi.dev/mcp"
    }
  }
}
  2. Open Customize > MCPs.
  3. Follow the sign-in prompt for zeusi.

VS Code (GitHub Copilot)

  1. Open the Command Palette and run MCP: Add Server (or Chat: Open Customizations > MCP Servers > Add Server).
  2. Choose HTTP and paste the server URL.
  3. Enter the server ID zeusi and choose Global.
  4. Sign in when VS Code asks.

Gemini CLI

  1. Add Zeusi in your terminal: 
    gemini mcp add --transport http zeusi https://mcp.zeusi.dev/mcp
  2. In Gemini CLI, sign in: 
    /mcp auth zeusi
  3. Sign in with GitHub and approve access.

Any MCP client

  1. Add a remote server with the URL https://mcp.zeusi.dev/mcp, transport Streamable HTTP.
  2. Choose OAuth sign-in (OAuth 2.1). Your client finds the Zeusi sign-in by itself.
  3. No OAuth? Send the header Authorization: Bearer $ZEUSI_READ_TOKEN. Ask your Zeusi admin for a read token.

What happens when you sign in

  1. Sign in with GitHub. Any GitHub account works. You get your own workspace. It is separate from everyone else’s and starts empty.
  2. Zeusi shows which app is asking and where access goes.
  3. You approve access once. Zeusi can read your workspace. It writes into your own workspace only after you approve a preview. You never paste a token.

Your first 5 minutes

  1. Add Zeusi to your AI app. Add https://mcp.zeusi.dev/mcp as a connector. The steps for your app are under Connect your AI.
  2. Sign in with GitHub and approve. No invite needed. You get your own workspace. It starts empty, and another user’s Zeusi sign-in cannot read it.
  3. Ask your assistant: “Run zeusi_startup”. You see “Hello, I’m Zeusi”. Zeusi tells you that your workspace is still empty.
  4. Ask: “What can Zeusi do?” Your assistant reads zeusi://about and explains what Zeusi does for it.
  5. Fill your memory. Say “fill my memory” and paste your notes, or point your assistant at an export. Zeusi shows a preview first, and nothing is saved until you say yes, once. If your assistant says it cannot write yet, reconnect the Zeusi connector once and approve access again. That gives write access to your own workspace. A nightly routine can keep it in sync. Never paste secrets (passwords, API keys, tokens) or private client details. To make a rule, write it in a note: list it under locks: in the note’s front matter, and mark it with standing_locks: [1] (the number of the lock). The import and the nightly sync both keep it, and Zeusi serves it at the start of every session. A decision-log entry becomes a decision only in this exact form. Anything else stays a searchable note, and the preview says why: 
    ## 2026-11-18T10:00:00+01:00 me
Decision: go
Said-at-precision: minute

Use preview first, then one explicit yes, for every import.
    Or as one JSONL line: {"kind":"go","who":"me","said_at":"2026-11-18T10:00:00+01:00","said_at_precision":"minute","exact_words":"..."}. Use me as the handle. That handle is your workspace’s own person, so the entry is saved as a decision. An entry with another handle is saved as a searchable note. So is an entry in an older workspace that does not know me yet. The preview and the commit result tell you when this happens.

What Zeusi remembers

Zeusi keeps decisions, standing rules and the notes they come from. Each one keeps its source, so your assistant can cite it.

What Zeusi is

Zeusi is a shared memory for decisions, digs, parked items and locks, named after a cat. It is not tied to one AI model. Every item keeps its source, so Claude, Grok, Cursor or any other assistant can show where an answer came from. Zeusi is read-only by default, and it never makes up a decision.

Zeusi speaks up first

Before your assistant starts a task, it can ask Zeusi what applies: past decisions, locks and parked items, each with its source, and any conflicts between them. If nothing applies, Zeusi says so.

A Zeusi decision is context, not permission. Decisions and locks returned by Zeusi are cited context for your assistant; they are not an approval or a GO to act now. Your assistant still needs your current, explicit approval for anything that needs one.

A connector cannot force a model to call a tool or run a script. Zeusi asks your assistant to check first, and offers a ready-made start-task prompt. Your assistant decides whether to follow it.

First run: an empty Zeusi

If your assistant finds your personal workspace empty, it can offer to fill it, with a preview first (step 5 of Your first 5 minutes). In a Zeusi you run yourself, it can offer the ready-made onboarding prompt instead. There you import your history yourself, on your own computer, with the zeusi command-line tool. It always starts with a dry run, which only counts what would be added and writes nothing: zeusi onboard --markdown <notes-folder> --scope work. Run the import command it prints only after you have checked those counts.

In a Zeusi you run yourself, your assistant cannot run the import for you, and a connector cannot force a model to run anything. The import filters out passwords, tokens and sign-in codes. Names, emails and phone numbers are not filtered out, so check your files first.

What not to put in it

Never put passwords, access tokens, sign-in codes or private client details in Zeusi.

Your workspace is kept apart from other users: another user’s Zeusi sign-in cannot read it. Your memory is encrypted. Only you hold the key. It is not hidden from the people who run Zeusi while you are signed in: the Zeusi server then decrypts your memory to answer your assistant. Whoever holds the admin database login can see that your workspace exists, how many items it holds, how large they are and when it changes. Your workspace is not end-to-end encrypted.
