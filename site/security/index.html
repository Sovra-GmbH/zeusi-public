Security

This page says how Zeusi is run today. It says only what the code and the live servers do now.

Where Zeusi runs

  • The Zeusi server (mcp.zeusi.dev) runs on Fly.io, in Frankfurt, Germany.
  • The database is Neon Postgres, in Frankfurt (EU).
  • This website (zeusi.ai) is a set of static files served by Vercel.

Connections

Zeusi answers over HTTPS only. The server has no plain-HTTP port, and the website sends plain-HTTP visits on to HTTPS. Both zeusi.ai and mcp.zeusi.dev tell browsers to use HTTPS only (HSTS).

Sign-in and access

  • You sign in with GitHub. Zeusi does not keep your GitHub token.
  • Your assistant then gets its own Zeusi access. An access token lasts 1 hour. The refresh token that renews it lasts 30 days. Zeusi stores only hashes of these tokens.
  • Each GitHub account outside the operator’s team gets its own workspace. Another user’s Zeusi sign-in cannot read it.
  • The operator’s own team workspace is separate from user workspaces.

What the people who run Zeusi can see

Your workspace is kept apart from other users.

Your memory is encrypted. Only you hold the key.

It is not hidden from the people who run Zeusi while you are signed in: the Zeusi server then decrypts your memory to answer your assistant. Whoever holds the admin database login can see that your workspace exists, how many items it holds, how large they are and when it changes.

Your workspace is not end-to-end encrypted.

They can also see that a workspace exists, when it was made, its status, how many items it holds, which assistants are connected to it (with your GitHub login), and the sign-in, write and key-setup records described below.

Checks before an answer leaves Zeusi

Before Zeusi sends an item to your assistant, it checks the item for passwords, keys and tokens, and for walled-off content. An item that fails a check is held back. Zeusi sends an item whole or not at all.

Logs

  • The server writes one log line per request: the time, a request id, an access id, a label for the kind of access, the tool, how long it took, counts, the status and the kind of error. It never logs your search words or the text of your items.
  • Each sign-in writes one record: the time, a request id, your GitHub user id, your GitHub login, your workspace id, the kind of sign-in and the result. It holds no email address and no IP address.
  • Each import preview, import and sync writes one record: the time, a request id, your GitHub user id, your workspace id, a short hash of your access, what was done, the result and counts. It never holds the text, a title or a file path.
  • Only when someone sets up or uses a workspace key: each key setup or unlock writes one record: the time, a request id, your workspace id, what was done, the result and a count of recovery attempts. It holds no key, no code, no token, no IP address and no text.

Reporting a security problem

Write to hello@sovra.ch.

If a breach of your data is likely to lead to a high risk for you, Sovra GmbH reports it to the FDPIC as soon as possible, as FADP art. 24 requires. Sovra GmbH also informs the people affected where the law requires it.
